# Project summary

GitFit (repo/slug MyGymApp) — a personal iOS gym-tracking app (single user, portrait-only). Expo SDK 57 + Expo Router v57, React 19, TypeScript strict. Web/Android are not targets; iOS-first decisions (SF Symbols via `expo-symbols`) are intentional.

Roadmap (in priority order):
1. ✅ Login (Supabase email/password + Google OAuth) — done
2. ✅ Workout logging: custom routines (create/edit in the Workouts tab), per-set reps/weight logging with steppers, rest timer, drag-reorder queue mid-session — done
3. ✅ History list with per-set detail + calendar (merged into Progress/Log) — done
4. ✅ Progress: strength graphs per movement + body-weight and steps tracking — done (steps are empty until HealthKit)
5. ✅ Supabase tables + RLS replacing the local AsyncStorage store — done (`supabase/migrations/`, `src/lib/store/remote.ts`)
6. ✅ Design overhaul "Electric. Editorial. Alive.": GitFit brand mark + app icons, near-black electric palette, Fraunces/DSEG7 type mix, bento layouts, floating pill tab bar, haptics — superseded by #11
7. ✅ Nutrition tab: meal/calorie/macro logging via USDA FoodData Central, recipe book, daily nutrition goals (6th tab; requires migration 0005) — done
8. ✅ Workout-session upgrade: previous-set/PR hints, per-exercise skip, save-or-discard end flow, smooth countdown ring + haptic choreography, muscle-group chips — done
9. ✅ Customizable goals (arbitrary weekly goals: computed metrics or manual +1 check-ins; requires migration 0006) + body metrics (weight/BMI/measurements entry & trend charts) moved from Log to Progress — done
10. Apple Health / calorie sync (settings toggle is a disabled placeholder; the steps series stays empty until then)
11. 🚧 Design overhaul v2 "Lime. Editorial. Grounded.": lime replaces blue as the sole accent, strict font jobs (DSEG7 demoted to live timers, serif for all other numerals), a text-contrast pass, then a flat pass — all gradients removed, cards defined by a grey fill instead of a stroke, tighter radii, a lime→grey halftone background, and a black tab bar with a lime indicator. Global foundations and the **Dashboard** IA pass are done; **the other five tabs still need their layout/IA passes** (the original overhaul's weakness was leaving screen organisation untouched).

# Architecture

- Routes live in `src/app/` (NOT root `app/`). Path alias `@/*` → `./src/*`.
- Root `_layout.tsx`: `GestureHandlerRootView` → dark nav theme → `AuthProvider` → `StoreProvider` → `Stack` with `Stack.Protected` guards keyed on the Supabase session — never add manual login redirects; flipping the guard handles navigation. `RootNavigator` also gates on `useStore().isHydrated`.
- `(tabs)/_layout.tsx`: JS `Tabs` from `expo-router/js-tabs` with a custom `tabBar` — `TabBar` (`src/components/tab-bar.tsx`), a grounded solid-black (`tabBarBackground`) block running the full width of the screen, flush to the bottom edge (no radius, no border, no float inset; height `TabBarHeight` + bottom safe-area padding, icons bottom-aligned so they sit near the home indicator). The active tab is **lime** — a reanimated lime bar on the bar's **top edge** that slides between tabs, plus a lime icon and bold lime label; inactive tabs are white at 0.7 opacity. No pill, no bubble. Tab presses fire `Haptics.selectionAsync()` only when actually changing tab. 6 tabs: dashboard, logging (titled "Log"), nutrition ("Food"), progress, workouts, settings. Scrollable tab content pads with `BottomTabInset` to clear the bar.
- `workout/choose.tsx`: modal picker for which routine to start, pushed from the dashboard's Start Workout button.
- `workout/[id].tsx`: active-session screen, full-screen push. State machine: exerciseReady (reorderable queue + inline exercise editor) → per set: setPending → setActive → resting → next; finished shows rings + animated summary. Saves a `Session` to the store on finish. Timers recompute from wall-clock timestamps, never tick counts; the work/rest countdown is `src/components/countdown-timer.tsx` (wall-clock completion + one linear reanimated ring sweep + haptic choreography: 10 s warning, 3-2-1 ticks, success at zero). The setPending target card shows the matching set from the last session (`lastExercisePerformance`), the all-time best (`exercisePR`), and a volt PR-ATTEMPT badge when the target tops it; exercise headers show muscle-group chips from `src/lib/muscles.ts` (keyword mapping, cosmetic only). Mid-workout escape hatches: Skip Set, Skip this exercise (remaining sets logged as skipped), and End → save-&-finish / discard.
- `history/[id].tsx`: per-session detail (sets × reps × weight + duration/calories).
- `routine/[id].tsx` (modal): create (`id === 'new'`) / edit / delete routines.
- `cardio-routine/[id].tsx` (modal): create/edit/delete cardio routines — name, schedule, activity type (`CardioActivityType`, icon from `src/lib/activity-icons.ts`, also used on the Workouts list and `TodayWorkoutCard` so an activity always wears the same glyph), and a **TARGET** section with independent Target Time / Target Distance toggles (styled like the activity chips' active state) — either, neither, or both can be active, each showing its own `Stepper` (divided when both are on); `durationMinutes` always tracks the time stepper's value regardless of whether Target Time is toggled on, since it's still needed for calorie/duration display elsewhere.
- `cardio/[id].tsx`: cardio session screen, full-screen push. Phases: idle (target summary + last-time/PR hints from `lastCardioPerformance`/`cardioRoutinePR`) → active (flat wall-clock-ticking `TimerText` stopwatch with a manual End button) → enteringDistance (manual, optional) → finished. "End workout" mid-session offers Save & finish vs. Discard, same shape as strength's `confirmEnd`.
- `(tabs)/logging.tsx` ("Log"): calendar week strip, the weekly-goal editor, daily check-off definitions, and water quick-logging; linked from the dashboard Today section (there is no separate `goals.tsx` modal). Goals are fully user-defined (uuid `id`, free `label`/`unit`, `target`) with a `metric` field saying how weekly progress is computed: `workouts`/`calories`/`cardio`/`water` derive from logged data (re-addable via preset chips when missing), `manual` goals count volt +1 check-ins stored as `goal_entries` rows. Requires migration `0006_custom_goals.sql`; `mapGoals` in `remote.ts` still reads the pre-0006 row shape so hydration degrades instead of failing. Water-specific UI (dashboard bottle, WATER card) keys off `metric === 'water'`.
- `(tabs)/dashboard.tsx` ("Home"): greeting → the **metric deck** → a TODAY bento (water widget + daily goals) → TODAY'S WORKOUT + a New Workout bar. The deck (`src/components/goal-deck.tsx`) is one lime card showing one metric at a time, swiped via an `Animated.ScrollView` pager; the `MetricGauge` half-circle (`metric-gauge.tsx`, white track + near-black sweep) is absolutely positioned and `pointerEvents="none"`, so it **stays put while the text pages beneath it**. Each page counter-translates by `TEXT_TRAVEL` so the copy slides a short distance rather than sweeping the card, and cross-fades with its neighbour (`FADE_DISTANCE` > 0.5 so they overlap instead of both hitting zero mid-swipe). The gauge value counts up via `AnimatedNumber` and the unit fades; the arc always keeps a minimum sweep (`MIN_SWEEP`) so an empty metric shows a black dot instead of the path unmounting. Cards come from `dashboardMetrics` in `derive.ts` — calories eaten (from `foodLogs` + `nutritionGoals ?? DEFAULT_NUTRITION_GOALS`, daily) first, then goals in the pinned `DECK_ORDER`; each metric reports over its natural period, so water and intake are **daily** while workouts/cardio/calories-burned/manual stay **weekly**.
- Dashboard, lower half: `DailyGoalsCard` (`daily-goals-card.tsx`) shows an "N OF M DONE" header + lime progress bar over top-aligned check-off rows, each with a 7-day streak strip from `checkoffWeek` in `derive.ts` (Sunday-anchored, read straight out of `checkoffLog` — no extra storage). `TodayWorkoutCard` (`today-workout-card.tsx`) renders the day's `scheduledRoutineTasks` with muscle chips (`src/lib/muscles.ts`), duration + estimated burn (`estimateRoutineCalories`), a collapsible exercise list, and a circular lime play button that starts **that** routine; it falls back to a rest-day card. Starting something unscheduled is the separate full-width lime **New Workout** bar below the card → `/workout/choose`. Scheduled workouts are **not** in the daily-goals card — they live only in the workout card.
- Body metrics live on the Progress tab ("BODY" + "MEASUREMENTS" sections): body-weight entry + chart, BMI/body-fat card (profile metadata from Settings), and per-measurement entry cards with sparkline trends (`measurementSeries` in `derive.ts`).
- `(tabs)/nutrition.tsx` ("Food"): day-by-day meal log (breakfast/lunch/dinner/snacks) with a calorie/macro summary vs. editable daily targets (`nutrition_goals`). Food rows push the `food/[id]` edit modal; per-meal Add Food pushes `food/search` (USDA FoodData Central text search via `src/lib/nutrition/usda-food-data-central.ts`, custom manual foods, and one-tap recipe-serving logging). `recipes` + `recipe/[id]` modals are the personal recipe book (manual ingredients; whole-recipe macros ÷ servings). Nutrients are snapshotted onto `food_logs` rows at log time — editing an amount rescales the snapshot proportionally; per-100g data never persists. Nutrition tables fetch separately in `fetchNutritionData` so a project without migration 0005 degrades to empty slices instead of failing hydration.
- **Data layer**: `StoreProvider` / `useStore()` (`src/providers/store-provider.tsx`) hydrates the whole per-user dataset from Supabase on login (`fetchStoreData` in `src/lib/store/remote.ts`) and mirrors each mutator with a fire-and-forget remote write after an optimistic in-memory update — screens never talk to Supabase directly. App types live in `src/lib/store/types.ts` (camelCase) and map 1:1 to the snake_case tables in `supabase/migrations/0001_initial_schema.sql`. Pure selectors live in `derive.ts` — screens stay declarative. Row ids are client-generated UUIDs (`makeId` in `src/lib/store/id.ts`, via `expo-crypto`). First login writes default goals (`src/lib/store/seed.ts`); everything else starts empty.
- Auth state: `useAuth()` from `src/providers/auth-provider.tsx` (also `updateProfile`/`updateEmail`/`updatePassword`; name & birthday live in Supabase `user_metadata`). Supabase client: `src/lib/supabase.ts`.

# Integrations

- **USDA FoodData Central**: nutrition lookup (`src/lib/nutrition/usda-food-data-central.ts`, `foods/search` text search restricted to Foundation/SR Legacy/Branded data types, per-100g macros keyed on standard FDC nutrient IDs, one retry on a network/5xx error). Requires a free key from `fdc.nal.usda.gov/api-key-signup` in `.env` as `EXPO_PUBLIC_USDA_API_KEY`. Only the search screen talks to it; logged entries never reference it again. Provider-agnostic result shape and gram/serving math live in `src/lib/nutrition/units.ts`, kept separate so swapping providers again wouldn't touch the search/recipe screens' unit logic.
- **Supabase**: auth, profile metadata, and all workout/goal/health data (per-user tables with RLS; schema in `supabase/migrations/`, applied via the dashboard SQL editor). Every table keys rows on `user_id default auth.uid()` with select/insert/update/delete policies scoped to the owner, so the client never sends `user_id`. Credentials come from `.env` (`EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`). Never commit `.env`; update `.env.example` when adding new vars. Restart the dev server after changing `.env`.
- **Google login**: browser OAuth via `expo-web-browser` + `supabase.auth.signInWithOAuth` (see `signInWithGoogle` in the auth provider). Redirect URLs must be registered in the Supabase dashboard.
- **Apple Health**: not integrated yet; will require a dev build (not Expo Go) when added. The Progress "Steps" series reads `StepsEntry[]` from the store — HealthKit will fill the same interface.

# Conventions — design language: "Lime. Editorial. Grounded."

The app reads as a disciplined editorial training tool: a flat near-black canvas textured only by a print-halftone dot field, ONE accent (electric lime) plus a neutral grey ramp for data, serif for headers and every number, sans for everything else, and seven-segment digits reserved strictly for live timers. Cards are flat grey rectangles with softened corners, defined by their fill. **All colour is flat — there are no gradients anywhere in the UI.** Still NO glassmorphism, frosted/translucent surfaces, drop shadows, or colour washes behind text.

- Reuse `ThemedText` / `ThemedView` (`src/components/`) and `Colors` / `RingColors` / `ChartColors` / `Radius` / `Motion` / `Spacing` / `Fonts` / `Type` from `src/constants/theme.ts` — no hardcoded spacing, radii, durations, colors, or font sizes.
- **Single fixed dark theme**, not the OS light/dark setting: `background` `#08080A` (neutral near-black), card `surface` `#0E0E11`, raised controls `surfaceElevated` `#17171B` (steppers, segmented tracks, inputs, dropdowns). `useTheme()` just returns `Colors` — no scheme context; don't reintroduce OS-based scheme switching or a light theme.
- **One accent — lime**: `primary` `#D4F53C` (≈17:1 on background), `primaryLight` `#E6FF85` (small icons/links), `primaryDark` `#9DBF1F` (gradient dark stop / pressed). **`onPrimary` `#08080A` is the ONLY correct content colour on a lime fill** — never `Colors.text` on lime; use `onPrimaryDim`/`onPrimaryFaint` for secondary text and empty marks on an inverted lime card. `success` aliases lime (wins are lime); `warning` `#F5A524` and `danger` `#FF5A52` are semantic-only and never chart series.
- **Lime budget**: lime *fills* are for genuinely primary actions (plus at most one inverted lime hero card per screen); secondary actions are border + lime text. The rule is one fill per *distinct* action, not one per screen — the dashboard carries three (the deck hero, the New Workout bar, and the scheduled workout's play button) because starting today's workout and starting an unscheduled one are different jobs. What the budget forbids is a wall of filled buttons doing similar things. Lime is used liberally as accent **text, icons, rings, and chart strokes** — that's where it should mostly read.
- **Text contrast**: values, numbers, and the units/targets attached to them are `Colors.text` (or `primary` for a win/PR). `textSecondary` `#A9AEB8` (≈9:1) is for labels, captions and eyebrows. `textMuted` `#878D99` is **disabled/placeholder state only** — never content. If a piece of grey text is the thing the user came to read, it's the wrong colour.
- **Backgrounds**: screens wrap content in `ScreenBackground` (`src/components/screen-background.tsx`) — flat base plus a print-halftone dot field in **three tiers** that grade coarse-and-lime at the top-left to fine-and-neutral at the bottom-right (`dotAccent` → `dotMid` → `dot`, each `Pattern` dissolved by a background-coloured scrim before the next is painted; no SVG `<Mask>`, no `viewBox` so the pitch stays constant). It takes no props. This is the only sanctioned background decoration and it must never compete with text — if it reads as busy, lower `Colors.dotAccent`'s alpha rather than changing the pitch.
- **Cards**: `surface` fill (`#16161A`) + `Radius.lg` (12) + `Spacing.three/four` padding, and **no stroke** — the fill is what defines a card. Buttons/inputs `Radius.md` (10), inner chips/segments `Radius.sm` (8); radii are deliberately tight so containers read as softened rectangles, not pills. Never use `Spacing.*` as a borderRadius. Prefer bento variety over uniform full-width stacks.
- **Borders are structural only.** An element keeps a 1px `Colors.border` **only when it has no fill** — text inputs, dividers (`borderTopWidth`), unchecked check circles, dashed placeholders, outline/secondary buttons, and inactive chips. Anything with a background colour must not also carry a stroke.
- **No gradients.** `GradientFill` and the `Gradients` tokens were deleted; buttons and cards are flat `Colors.primary` / `Colors.surface`, with `primaryDark` as the pressed state. The only remaining `LinearGradient` in the app is `ScreenBackground`'s halftone falloff scrim, which is texture, not a fill. No `expo-linear-gradient`. Gradient text remains off-limits.
- **Data colors**: `RingColors` (outermost first: lime, then down a neutral grey ramp) and `ChartColors` live in theme.ts — change them there, not per-screen. The chart rule: **effort metrics you push on are lime** (steps, cardio, strength), **measurements you merely record are neutral** (calories, water, bodyweight). No second hue.
- **Motion**: all animations `withTiming` with `Motion.fast/base/slow` (150/200/250 ms) — no springs, no long animations. Count-up numbers (`AnimatedNumber`, 800 ms ease-out) are the one sanctioned longer animation. Reanimated 4: use `sharedValue.get()/.set()`, not `.value` (the React Compiler lint rejects `.value` assignment).
- **`AnimatedNumber` is deliberately JS-driven** (`requestAnimationFrame` + state, rendering a real `<Text>`), not Reanimated. The usual trick — an animated `text` prop on a `TextInput` — writes to the native view without re-running layout, so the box keeps the width React last rendered (`"0"`, one character) and multi-digit values are **clipped to their first digit** until something forces a re-measure. Don't "optimise" it back onto the UI thread.
- **Fonts — three voices with strict jobs** (loaded in the root layout):
  - **Manrope** (`Fonts.regular/medium/semibold/bold`) — body copy, labels, buttons, list rows, chart month names. The default for anything that isn't a header or a number.
  - **Fraunces serif** (`Fonts.display/displayBold/displayItalic`) — headers (`display`/`title`/`subtitle`/`heading`) AND **every number that isn't a live timer**: `stat`/`statLarge`/`statSmall` for standalone stats, `statInline` (15 px) for numerals sitting inside a sans text row, plus `AnimatedNumber`, `SummaryStat`, and SVG chart axis numerals. Nest `type="displayItalic"` for the serif-italic emphasis word inside display copy.
  - **DSEG7 Classic** (`Fonts.timer/timerLight`, bundled in `assets/fonts/` with its OFL license) — **live workout/cardio timers and in-session distance ONLY**. That means exactly `CountdownTimer` (work/rest), the elapsed timer on `cardio/[id].tsx` and `workout/[id].tsx`, and the live cardio distance readout. It is NOT a number face: post-session summaries, targets, goals, counters, and stat tiles are all serif. Digits-only — never set labels in it.
  - Sizes come from the `Type` scale in theme.ts. Uppercase section eyebrows use `ThemedText type="label"` (letter-spacing is baked in — don't re-add it per screen).
- **Haptics** (`expo-haptics`): `selectionAsync` on tab/segment switches, `impactAsync(Light)` on set completion, `notificationAsync(Success)` when a countdown finishes. Keep haptics on meaningful moments only.
- **Brand**: the "commit-graph dumbbell" mark — geometry in `src/constants/brand.ts`, rendered in-app by `GitFitLogo` (`src/components/gitfit-logo.tsx`). App icons/splash/favicon PNGs are generated from the same geometry by `npm run generate:brand` (`scripts/generate-brand-assets.mjs`, dev-only `sharp`); regenerate instead of hand-editing PNGs, and keep the script's inlined geometry in sync with `brand.ts`.
- Charts are hand-rolled `react-native-svg` (`line-chart.tsx` — pass `sparkline` for compact tiles; `contribution-grid.tsx` — dot-matrix, pass `inverted` on bright cards; `activity-rings.tsx`) — no chart library.
- Kebab-case file names (`auth-provider.tsx`), `StyleSheet.create` at the bottom of the file. Shared helpers: `formatDuration` in `src/lib/format.ts`, `SummaryStat` in `src/components/summary-stat.tsx` (pass `animatedValue` for count-up) — don't re-declare them per screen.
- Routine `tileColor` is still stored in Supabase but is no longer read for rendering (legacy rows hold old-palette values); routine tiles render an SF-symbol over a flat `primaryTint` fill.
- Screens under the tab bar pad scrollable content with `BottomTabInset` (`TabBarHeight + 56` = 108) so it clears the bar.

# Testing & verification

There is no test suite yet. Verify changes with, in order:
1. `npx tsc --noEmit` — must pass. (If it complains about missing `expo-env.d.ts` / CSS module types on a fresh clone, or about a route string you just added, run `npx expo start` once to regenerate typed routes.)
2. `npm run lint` — must pass clean, no known pre-existing errors.
3. Metro bundle smoke test (catches broken imports across all routes): start `npx expo start --port 8090` and curl
   `'http://localhost:8090/node_modules/expo-router/entry.bundle?platform=ios&dev=true&transform.routerRoot=src/app'` — expect HTTP 200 and ~11 MB.
   **`transform.routerRoot=src/app` is required.** Routes live in `src/app`, so without it expo-router's `require.context` resolves to the (empty) default root, Metro happily returns 200 with a ~5.9 MB bundle containing **no screens at all**, and the test proves nothing. Sanity-check by grepping the output for a string you just added; a bundle that doesn't contain your code didn't test it.
4. iOS simulator testing: Xcode is installed (iPhone 17 simulators) — `npx expo start` then press `i` installs an SDK-matching Expo Go in the simulator automatically. Real-device testing via Expo Go on the user's iPhone (`npm start` + QR scan; keep the phone's Expo Go updated so its SDK matches). Ask the user to verify device-only feel (haptics, sliders, drag-reorder, keyboard handling); OAuth redirects work in the simulator too.

When adding a test framework later, prefer `jest-expo` + React Native Testing Library.
